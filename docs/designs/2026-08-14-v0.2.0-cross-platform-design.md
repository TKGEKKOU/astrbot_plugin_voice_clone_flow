# VoiceClone Flow v0.2.0 跨平台适配设计

## 目标

在不改变 AstrBot 平台源码、不破坏现有 Windows 流程的前提下，使 VoiceClone Flow 能够自动识别 Windows 与 Linux，并在用户执行资源下载、服务启停和训练操作时选择正确的平台实现。

本次适配解决真实运行链路，而不仅是绕过 Linux 无法执行 `7zr.exe` 的表面错误。

## 范围

### 包含

- 统一识别操作系统、架构和关键运行依赖。
- FFmpeg 下载或安装引导按平台分流。
- GPT-SoVITS 安装按平台分流。
- GPT-SoVITS Python 与 API 入口跨平台探测。
- GPT-SoVITS 服务启动、停止和孤儿进程处理跨平台。
- 训练流程复用统一的 Python 与 FFmpeg 路径。
- Linux 无桌面环境下的目录操作降级。
- 页面展示当前平台、资源状态和可执行的下一步。
- Windows、Linux 关键分支测试。

### 不包含

- 插件自动执行 `sudo`、`apt`、`dnf` 或修改系统软件源。
- 自动安装或修改 NVIDIA 驱动、CUDA 驱动。
- Wine 或在 Linux 上运行 Windows GPT-SoVITS 整合包。
- macOS 支持。
- 本版本新增远程 GPT-SoVITS 推理模式。

## 核心原则

### 检测时机

平台类型本身在插件进程生命周期内保持不变，但资源状态可能被外部修改。因此采用两级检测：

1. 插件初始化及页面刷新时执行轻量检测，用于展示平台和资源状态。
2. 每次点击下载、启动、停止、训练等按钮时重新检测与该操作有关的依赖，检测通过后才执行。

前端不根据浏览器 User-Agent 判断系统。所有判断均由 AstrBot 服务端完成。

### 权限边界

插件可以管理 `data/plugin_data/astrbot_plugin_voice_clone_flow/` 下的文件和自己启动的进程，但不得尝试提权。Linux 系统依赖缺失时返回明确的安装命令，由用户在服务器终端执行。

## 平台模型

新增统一的 `PlatformProfile`，至少提供：

- `system`: `windows` 或 `linux`
- `architecture`: 规范化架构名称
- `is_desktop_available`: 是否适合打开本地文件管理器
- `python_candidates`: 当前平台允许探测的 Python 候选
- `archive_tools`: 当前平台允许使用的解压器
- `ffmpeg_path`: 当前解析到的 FFmpeg
- `dependency_status`: Git、7-Zip、FFmpeg、Python、CUDA/PyTorch 等状态

系统名称使用 `platform.system()`，架构使用 `platform.machine()`。业务模块不再各自判断 `os.name` 或拼接 `.exe`。

## 操作分流

### FFmpeg

Windows：

- 保留现有系统路径检测和 Windows ZIP 下载流程。
- 托管文件仍为 `runtime/ffmpeg/ffmpeg.exe` 与 `ffprobe.exe`。

Linux：

- 优先通过 `PATH` 检测 `ffmpeg` 和 `ffprobe`。
- 点击下载时不下载 Windows ZIP。
- 缺失时返回适合当前发行版的安装提示；首版至少提供 Debian/Ubuntu 通用命令，同时允许用户自行配置绝对路径。
- 不自动执行包管理器命令。

### 人声分离模型

ONNX 模型文件跨平台共用同一下载源、校验值和存储位置。点击下载时仍检查平台信息，但无需拆分模型资源。

执行素材处理前检查当前 Python 环境能否导入可用的 ONNX Runtime；缺失时给出环境错误，不重新下载模型。

### GPT-SoVITS

Windows：

- 保留当前 v2Pro Windows 整合包、内置 `7zr.exe`、补丁覆盖和精简流程。
- 内置 `7zr.exe` 仅允许在 Windows 分支使用。

Linux：

- 不使用包含 `runtime/python.exe` 的 Windows 整合包。
- 采用 Linux 原生安装策略，在插件数据目录中准备 GPT-SoVITS 源码、受控 Python 虚拟环境、Python 依赖和预训练模型。
- 压缩资源只允许使用系统 `7z` 或 `7za`；缺失时返回安装提示。
- 安装产物位于插件数据目录，不能写入插件源码目录。
- 安装过程继续支持阶段、百分比、取消和明确错误反馈。

Linux 安装需要区分系统依赖与插件可管理依赖：系统依赖只检测和提示，源码、虚拟环境、Python 包与模型由插件安装流程管理。

## 安装探测

`probe_installation()` 改为平台无关探测，Python 候选顺序如下：

1. 用户显式配置的 Python 路径。
2. `<install_dir>/.venv/bin/python`。
3. `<install_dir>/venv/bin/python`。
4. Windows 的 `<install_dir>/runtime/python.exe`。
5. Windows 的 `<install_dir>/python.exe`。

API 入口继续探测 `api_v2.py` 和 `api.py`。探测结果增加平台、Python 来源和缺失组件，供页面显示具体原因。

不把系统全局 Python 直接视为完整 GPT-SoVITS 环境，避免误用 AstrBot 自身环境。

## 服务生命周期

### Windows

保留现有子进程、Job Object、`netstat -ano` 和 `taskkill` 行为。

### Linux

- 启动 API 时创建独立进程组。
- 正常停止先向插件追踪的进程组发送 `SIGTERM`，超时后发送 `SIGKILL`。
- 不调用 `taskkill`，不解析 Windows `netstat` 输出。
- 对插件未追踪但占用端口的进程，只报告端口占用及 PID；默认不强杀不属于当前插件实例的进程。
- 插件卸载或停用时停止自己启动的服务。

健康检查继续通过本地端口和 API 请求完成，不因平台变化。

## 训练链路

训练服务从统一安装探测结果取得 Python，从 FFmpeg 资源管理器取得 FFmpeg，不再拼接 `ffmpeg.exe`。

点击开始训练时重新验证：

- 本地 GPT-SoVITS 安装完整。
- Python 可执行且能加载必要依赖。
- FFmpeg 可执行。
- 训练数据存在且合法。
- PyTorch 设备状态明确。

CPU 或无 CUDA 环境是否允许训练由 GPT-SoVITS 实际能力决定；页面必须明确展示当前设备和预期性能，不能把“Python 存在”等同于“可以训练”。

## 目录操作

Windows 使用资源管理器打开音色目录。

Linux：

- 有桌面环境且存在 `xdg-open` 时可以打开目录。
- 常见无桌面服务器只返回并展示绝对路径，不尝试调用 `explorer`。
- 页面文案应说明该路径位于 AstrBot 服务器，而非访问页面的用户电脑。

## API 与页面状态

运行环境状态接口增加：

- 平台与架构。
- 操作能力，例如能否自动下载 FFmpeg、能否安装 GPT-SoVITS、能否打开目录。
- 缺失系统依赖及建议命令。
- 当前 GPT-SoVITS 安装类型与 Python 来源。

下载按钮点击后由后端再次检测并返回实际选择的策略。前端只依据后端能力渲染按钮和错误，不复制平台判断逻辑。

## 错误处理

错误按阶段区分：

- `unsupported_platform`
- `missing_system_dependency`
- `download_failed`
- `extract_failed`
- `environment_create_failed`
- `dependency_install_failed`
- `model_prepare_failed`
- `verification_failed`
- `service_start_failed`
- `training_environment_invalid`

用户提示必须包含发生阶段、根因和可执行的下一步。日志保留完整底层异常，但 API 不返回密钥或敏感环境变量。

## 兼容与迁移

- Windows 现有安装目录和配置继续可识别，不要求重新下载。
- Linux 上此前下载的 Windows `.7z` 缓存不作为有效 Linux 安装源，也不自动删除；页面提示其不兼容，由用户确认后处理。
- 音色目录结构和 Provider ID 保持不变。
- 外部导入的 `gpt.ckpt`、`sovits.pth`、参考音频和标注信息继续跨平台识别，但文件中若含旧系统绝对路径，需要重新登记。

## 测试与验收

### 自动测试

- Windows 与 Linux 平台识别。
- FFmpeg 候选和下载策略分流。
- Linux 分支绝不选择 `.exe` 解压器。
- Windows 与 Linux Python 候选探测。
- Windows 与 Linux 服务停止策略。
- Linux 无桌面环境目录操作降级。
- 各按钮执行前会重新探测依赖。
- Windows 现有配置兼容。

### 人工验收

Windows：现有下载、启动、训练、推理链路无回归。

Ubuntu：

1. 页面正确显示 Linux 与架构。
2. FFmpeg 存在时直接识别，缺失时不下载 Windows ZIP。
3. GPT-SoVITS 下载不调用 `7zr.exe`，也不安装 `python.exe`。
4. Linux 原生安装完成后能启动和停止 API。
5. 可使用已登记音色完成一次 TTS 推理。
6. 具备训练环境时可完成一次最小训练；环境不足时给出明确原因。

## 实施顺序

1. 平台检测与能力模型。
2. FFmpeg、目录操作和安装探测跨平台化。
3. GPT-SoVITS Windows/Linux 安装策略拆分。
4. 服务生命周期跨平台化。
5. 训练路径与执行前检查统一。
6. 页面状态与错误反馈。
7. 测试、版本号、变更日志和 Linux 文档。
